# Linux host (GTK4)

The only first-party SyncPilot host (SyncPilot is a Linux-only product): a
GTK4 window over one embedded Racket CS backend, speaking RVT1 through the
shared `runtime/` codec. The backend owns the rslsync daemon and the
auth-injecting reverse proxy; the host only renders and interacts.

Status: **written, not yet compile-verified** — the code was authored
off-platform (no GTK4/WebKitGTK on the authoring machine) against the real
generated client (`linux/GeneratedBackend.hpp`) and the Rivet Linux runtime
contract. First build must happen on a Linux box; expect small API-level
fixes.

## What it does

Parity with the Tauri app v0.4.0 (minus the gaps listed below):

1. **Boot page** (1160×760 window, min 960×620): a centered card that calls
   `initialize` then `get-handoff` over RPC. On success the window swaps to
   the web view; on failure it shows the specific backend error with a
   Retry button and an "Open SyncPilot Settings" button. When the error is
   the fixed "binary not found" message, the card offers "Download Resilio
   Sync (~15 MB)" wired to the `install-rslsync` RPC (button disabled with
   "Downloading…" while it runs; success toasts the installed path and the
   handoff retries automatically).
2. **Web view**: a WebKitGTK 6.0 `WebKitWebView` loading the proxy URL
   (`http://127.0.0.1:<port>/gui/`). The Racket backend injects basic auth
   into every request, so the view needs no credentials.
3. **Settings window** (720×640): Daemon card (rslsync binary path entry +
   detected-path label + Restart Daemon + start-with-app / restart-on-crash
   / keep-daemon-on-exit checkboxes + Regenerate Web UI password), Device
   card (device name entry + local API port spin 1024–65535), Desktop card
   (Launch at login via the rivet `rivet::system::Autostart` XDG adapter;
   Hide-to-tray shown insensitive — no tray in v1), About card (version,
   AGPL, GitHub link). Save calls `save-settings`; changing the port toasts
   "Saved. Restart the daemon to apply the new port."
4. **Daemon state surfacing**: the `daemon-changed` event is decoded on the
   backend reader thread and dispatched to the main loop. `crashed`/`failed`
   while in the web view flip back to the boot page with the error + Retry;
   other non-running phases show a thin top banner with the phase.
5. **Toasts**: small bottom-right banners (ok/err), auto-hide ≈3.4s, same
   timing as the old web UI.
6. **Single instance**: a second launch forwards to the running instance
   (which presents its window) via `rivet::system::SingleInstanceLease`.
7. **i18n**: all user-visible product strings come from
   `linux/GeneratedStrings.h`, generated from `shared/i18n/{zh,en}.json` by
   `scripts/gen-c-strings.mjs` (zh is the default; named `{placeholder}`s in
   the JSON are bound positionally by `l10n::t`).

## Build requirements

- CMake ≥ 3.24, pkg-config, a C++20 compiler
- GTK 4 (`pkg-config gtk4`)
- WebKitGTK 6.0 (`pkg-config webkitgtk-6.0`, Ubuntu 24.04+) — **optional at
  build time**: without it the host compiles with `HAVE_WEBKIT` unset and
  the boot page explains that the embedded official UI needs webkitgtk-6.0,
  offering "open in browser" + Settings instead. The settings window works
  either way.
- zlib, LZ4, curses
- An embeddable Racket CS build (`libracketcs` + the three boot files; the
  standard prebuilt installer does not ship them — same requirement as every
  Rivet Linux host)

## Building

The normal flow, from the repo root on Linux:

```bash
raco rivet build    # regenerates clients, compiles the backend bundle,
                    # stages runtime/ + res/, drives this CMake project
raco rivet dev      # develop loop: rebuild + relaunch on change
```

By hand (same environment variables `raco rivet build` would set):

```bash
export RIVET_ROOT=/path/to/rivet
export RIVET_RACKET_INCLUDE=/path/to/racket/include
export RIVET_RACKET_LIBRARY=/path/to/racket/lib/libracketcs.a
cmake -S linux -B /tmp/syncpilot-linux-build
cmake --build /tmp/syncpilot-linux-build
```

The executable must sit beside a staged runtime (`runtime/*.boot` and
`res/core.zo`) to start; `raco rivet build`/`dev`/`package` create that
layout.

Regenerate the strings header after editing `shared/i18n/*.json`:

```bash
node scripts/gen-c-strings.mjs
```

## Layout

```text
linux/
├── CMakeLists.txt         # GTK4 required, WebKitGTK 6.0 optional (HAVE_WEBKIT)
├── GeneratedBackend.hpp   # generated by raco rivet build/generate — do not edit
├── GeneratedStrings.h     # generated by scripts/gen-c-strings.mjs — do not edit
└── src/
    ├── main.cpp           # app bootstrap, boot page, web view, daemon events
    ├── settings_window.cpp/.h   # standalone settings window
    ├── toast.cpp/.h       # in-window notification banners
    └── dispatch.h         # backend-thread → GTK-main-loop bridge (shared)
```

## Honest gaps (v1)

- **Not yet compiled.** The host was written against the generated client
  and the Rivet Linux runtime headers, off a machine with no GTK4. Treat the
  first Linux build as the real review: expect include/signature-level
  adjustments only (logic and RPC names are taken verbatim from
  `linux/GeneratedBackend.hpp`).
- **No tray** (and therefore no close-to-tray): `rivet::system` has no
  Linux tray contract — StatusNotifierItem hosting is compositor-dependent
  (GNOME needs an extension), an upstream gap. The settings row is shown
  insensitive so the stored setting stays visible but inert.
- **No in-app updates**: the old deb/AppImage updater is replaced later by
  the rivet release flow. No updates card in the settings window.
- **No native folder picker** for the rslsync path: plain entry field (the
  old app's file dialog is not reproduced).
- **No window icon/logo art** on the boot page (title text only).
- **Language**: zh by default; `l10n::language` is switchable at runtime but
  no in-app switcher yet.
