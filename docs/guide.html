🚀五分钟上手

装好、启动、连上 Resilio Sync。到这里就能用了——其余内容都是可选的。

  1. 安装。到 Releases 页选对应架构的包：deb 用 sudo apt install ./…deb，rpm 用 sudo dnf install ./…rpm，AppImage 加可执行权限直接运行。不想安装就解压 tar.gz / zip，运行其中的 RivetHost。x64 与 arm64 全格式齐备。
  2. 首次启动。从应用菜单打开 SyncPilot（deb/rpm 装在 /opt/syncpilot，带桌面入口）。还没有官方 rslsync 二进制？启动页一键从 Resilio 官方 CDN 下载（约 15 MB，sha256 校验后装入 ~/.local/bin）。也可以自行安装后到设置里指定路径——自动探测覆盖 ~/.local/bin、/usr/bin、/usr/local/bin、/opt/resilio-sync 和 $PATH。
  3. 连上 Resilio Sync。窗口里加载的就是官方 Web UI。在官方面板登录或激活、添加同步文件夹——与 Windows、macOS 上完全一致，没有要重新学的东西。
  4. 管好守护进程。SyncPilot 默认随应用启动并看护 rslsync：崩了按退避自动重启，退出应用默认保活。设置窗口的 Daemon 卡片可随时重启。
  5. 按需调整。设置 → Desktop 卡片：开机自启、关闭到托盘、界面语言。改端口后按提示重启守护进程生效。

🔄守护进程启停

SyncPilot 管理官方 rslsync 守护进程的一生：启动、接管、停止、保活。

启动

默认随应用一起启动。也接管已在运行的守护进程——systemd 服务、上次会话遗留的都行。不兼容的守护进程会明确报错，绝不盲接管。

停止 / 重启

设置窗口 → Daemon 卡片 → Restart Daemon。退出应用时默认保活守护进程（keep-daemon-on-exit），关窗后照样同步；想一起退出就取消勾选。

凭据

Web UI 登录名固定 syncpilot，密码首次启动随机生成。想换：Daemon 卡片 → Regenerate Web UI password。

指定 rslsync 路径

自行安装了官方二进制？在 Daemon 卡片填入路径，或留空交给自动探测。

🛡️看门狗与状态

守护进程有五个状态：stopped / starting / running / crashed / failed。状态不正常时窗口顶部出现细横幅；崩溃或启动失败会弹回启动页，给出具体错误和重试按钮。

崩溃看护

restart-on-crash 默认开。守护进程崩溃后按指数退避自动重启：2s 起、每次翻倍、60s 封顶——不会陷入疯狂重启。

不想等？

设置 → Daemon → Restart Daemon，立即手动拉起。

⚙️配置编辑

SyncPilot 在数据目录生成 rslsync.conf，再启动守护进程。文件权限 0600，凭据不出本机。

# 数据目录里的配置文件（路径见下方 FAQ） $ cat ~/.local/share/site.jrtx.syncpilot/rslsync.conf
⚠️ 手改会被覆盖
conf 在每次启动守护进程前重新生成。要改端口、设备名或凭据，请用设置窗口——手改 rslsync.conf 会在下次启动时丢失。

改端口

设置 → Device → 本地 API 端口（1024–65535）。保存后按提示重启守护进程生效。

改设备名

设置 → Device。默认取自 /etc/hostname，改名即写入 conf。

🔌端口与代理

窗口里的官方界面不直连守护进程。SyncPilot 在本机开一个随机端口的环回代理，给每个请求注入认证，再转发给 127.0.0.1:<端口> 上的 Web UI（默认 38889）。这层不需要配置。

无需登录

认证由代理注入，你永远看不到登录框；守护进程绝不响应未认证请求。

仅环回

Web UI 只绑定 127.0.0.1，外部机器无法访问。所有 P2P 流量由官方 rslsync 自己处理，SyncPilot 不经手。

密码不回显

Web UI 密码只写进本地 conf 与设置文件，不通过 RPC 回显到任何界面。

🖥️自启动与托盘

都在设置 → Desktop 卡片里。

开机自启

打开 Launch at login，写入 XDG autostart 项；关掉即移除。随自启拉起的窗口可从托盘找回。

关闭到托盘

默认开。点关闭只是隐藏窗口，托盘菜单 Open 回来；退出请走托盘 Quit。桌面没有托盘宿主时该项置灰——关窗即退出应用，保活的守护进程继续同步。

单实例

重复启动只会唤起已有窗口，不会开出第二个实例。

📁数据存在哪里？

全部在用户目录下，没有散落：

# 尊重 XDG_DATA_HOME，默认在这里 ~/.local/share/site.jrtx.syncpilot/ ├─ syncpilot-settings.json # 应用设置（含生成的凭据） ├─ rslsync.conf # 守护进程配置（0600） ├─ storage/ # rslsync 内部状态（设备身份、共享密钥） └─ updates/ # 更新器下载并验签过的 tar.gz

rslsync 本体

首启一键下载时装在 ~/.local/bin/rslsync。

同步的文件

在你通过官方界面添加的文件夹里，就是普通文件，随时可访问。

迁移

整个数据目录一起搬即可，路径与格式跨版本不变。storage/ 里是设备身份，删了要重新激活，慎删。

🔑需要 root 吗？

日常使用不需要。守护进程以你的用户身份运行，数据全在 ~ 下。只有安装 deb/rpm 时包管理器要一次管理员权限；AppImage 与 tar.gz/zip 从下载到运行全程免 root。

🐧支持哪些平台？

SyncPilot 是 Linux-only 产品——GTK4 + WebKitGTK 6.0 宿主是唯一的第一方宿主，没有 macOS 或 Windows 版本。

发行版

Ubuntu 24.04+ 开箱即用（GTK 4 / WebKitGTK 6.0 系统自带）。更老的发行版选 AppImage——它自带 GTK4 依赖闭包。

架构

x64 与 arm64，五种格式全齐备（deb / rpm / AppImage / tar.gz / zip）。

桌面环境

托盘是否可用由桌面决定：没有托盘宿主时，设置里的关闭到托盘置灰。窗口深浅色跟随系统 GTK 主题。

🌐怎么换语言和主题？

应用语言默认跟随系统。设置 → Desktop → Language，选 跟随系统 / 简体中文 / English；保存后下次启动生效（保存时会提示重启）。应用窗口样式跟随 GTK 系统主题。

本站（产品页）右上有语言和 ◐ 主题切换，选择会被记住；不选则跟随浏览器语言与系统深浅色。

⬆️怎么更新？

应用内更新器每天静默检查一次 Ed25519 签名的 update-stable.json feed。想立刻查：设置 → Check for updates（不受 24 小时节流限制）。

  1. 有新版 → 应用内下载。字节数与 SHA-256 先对签名 manifest 核验，通过才交给你。
  2. 验证过的 tar.gz 落在数据目录的 updates/ 下，并有打开文件夹的入口。
  3. 手动应用：把 tar.gz 解压覆盖应用目录（tar.gz / zip 安装的用户），重启 RivetHost。deb / rpm 用户更简单：直接下载安装新版包即可。
🔒 rslsync 数据绝不触碰
更新器只写 updates/ 目录；设置、凭据、storage/ 与已同步文件全部原样保留。

0.7.x 起用的就是这条 update-stable.json feed——在应用内「检查更新」即可直接升上来。0.6.1 及更早版本的下载器有 302 重定向缺陷（0.7.0 已修复），请手动下载新安装包升级一次，此后一切自动。

🗑️怎么卸载？

  1. 先关自启：设置 → Desktop → Launch at login 关掉（会移除自启项）。
  2. 删应用：deb 用 sudo apt remove syncpilot；rpm 用 sudo dnf remove syncpilot；AppImage / tar.gz / zip 删文件或目录即可。
  3. 删数据（可选）：rm -rf ~/.local/share/site.jrtx.syncpilot；rslsync 本体若是 SyncPilot 代装的，再删 ~/.local/bin/rslsync。
⚠️ 删数据前想清楚
已同步文件夹里的文件不受影响；但删除数据目录会丢设备身份与共享密钥，删前确认不再需要。
